Wework 设备身份与历史记录兼容

发布与数据边界​

本功能不需要新增数据库字段、唯一索引或运行数据清理 SQL。部署新版后端和前端后， 让 Wework 重新连接以建立按记录隔离的在线路由。新版后端应完成统一发布后再验证， 不要把仍由旧版后端维护的连接当作新路由的验证结果。 正常注册和用户主动删除仍会通过业务接口更新设备记录；“不操作线上数据库”指无需人工 SQL 或批量迁移， 并非禁止这些正常业务写入。

身份与记录路由​

  • device_id：新 Wework 安装生成并持久化 UUIDv4，重启不变。已有 ID（包括 local-device）和显式配置保持不变。
  • runtime_instance_id：持久化 Runtime 安装身份，用于校验注册和心跳。
  • app_device_id：桌面 IPC 身份，不替代逻辑设备 ID。
  • execution_target_id：后端对 app 记录返回 app-record-<主键>，用于精确执行路由；界面仍展示原 device_id。

新配置的生成和保存受文件锁保护，采用同目录临时文件原子替换。配置损坏或保存失败会明确报错， 不使用所有安装共用的兜底 ID，也不丢弃旧配置重新生成身份。

注册按用户、默认命名空间、设备 ID、Runtime 和 IPC 身份匹配。完全相同的历史重复记录选择稳定主键； 不同安装保留各自记录、在线状态与执行路由。无法确认归属时拒绝注册或路由，不按显示名猜测。 注册使用已有用户行的事务锁，并用 Redis 锁覆盖注册到上线、删除的竞争窗口，不依赖新增唯一索引。

设备记录删除​

在设备卡片菜单中选择删除并确认，前端提交记录主键。Wework、远程和本地设备仅在离线且没有未完成任务时允许删除； 只有云设备允许在线或繁忙时删除。后端两个删除入口都重新校验归属和上述规则， 受保护的在线或繁忙设备返回冲突，其他用户的记录返回不存在。仅软停用指定记录，保留任务历史和本地文件； 同一安装再次连接时可恢复该记录。确认框会说明这一行为。

历史任务、项目或默认设备引用不会批量改写。唯一的旧 ID 可解析到对应记录；同名且属于不同安装的旧引用 无法安全推断归属，需要用户明确选择设备，不能静默切换到其他设备。删除不是把一台安装迁移到另一台安装。

插件安装状态​

插件安装、更新、同步回执与市场查询使用同一设备身份：app 使用 app-record-<主键>，其他设备使用逻辑 ID。 已确认属于同一安装的旧逻辑 ID、IPC 别名记录，在读取时按最近同步结果合并，后续业务写入时收敛；保留失败原因与重试次数，不需要清空用户插件目录。 更新成功以设备实际 release 等于目标 release 为准，HTTP 成功或旧记录的 installed 状态不能单独证明新包已安装。 桌面卸载后立即刷新详情中的安装状态。后端和桌面端都需要发布，单独发布插件包不能修复宿主状态管理。

桌面 plugin-auto-update 检查点覆盖生成的最小插件包跨版本升级、取消、目录刷新、卸载与重装，以及六插件后台升级。 测试复用真实发布接口，每版仅生成 manifest 和两个技能文本文件，验证技能内容替换、新增与删除、旧版本目录清理；不需要提交历史业务包或二进制测试归档。 macOS 空闲任务的可用内存计算包含可回收文件缓存，避免在仍有可用内存时无限推迟自动更新。

QA 与 CI​

使用隔离数据库、Redis、测试用户和 Electron profile，不连接生产库或个人 Wework 窗口。

场景验证与预期
并发注册与重连同一安装三路真实 Socket.IO 注册，只创建一条记录；断开重连复用主键
历史重复测试夹具插入同 ID 的相同与不同 Runtime 记录；精确匹配，彼此心跳和在线状态独立；仍拒绝 app 远程控制
删除与恢复在线 Wework 删除被拒绝；跨用户删除被拒绝；页面确认只删所选离线记录；重连恢复原主键
类型与删除规则在线 Wework、远程、本地设备的菜单和两个 API 入口均禁止删除；云设备在线可确认删除；设备在确认期间上线后禁止提交
UUID 持久化新安装 UUIDv4，重启与并发启动不变；不同目录不同 ID；已有 ID 保留；损坏配置失败
默认与历史引用唯一旧 ID 可解析，歧义 ID 不猜测，历史任务 JSON 不改写
对话与桌面从 Wework 设备发起对话、回复与追问；真实桌面首次注册得到 UUID 和记录路由

frontend/e2e/tests/devices/app-device-identity.spec.ts 由平台 CI 的 chromium 分片执行； tasks/agent-conversation-regression.spec.ts 的 app 对话由 executor-chromium job 执行。 桌面验证扩展已有共享 runner 的 remote-device-onboarding 检查点，由桌面 CI 执行。 单元测试覆盖归属、未完成任务保护、历史引用及并发持久化。交付时另行记录实际执行结果，不以覆盖存在代替通过证明。
