项目助理托管状态设计

本交付包含共享展示组件、只读投影 adapter、合成原型与验收计划，用于评审“我的助理在此项目”的状态表达。它尚未接入生产页面、Backend API、设备心跳或分配调度，不能作为功能已上线的证据。

用户结果与两个入口​

项目概览和助理首页应消费同一份当前用户、存储类型、项目的服务端快照。用户能直接判断托管是否开启、覆盖哪个项目和 Tag、当前 Tag 是否匹配、设备是否可用，以及最近一次真实接单的时间。助理首页切换项目时必须同时切换完整上下文，不能沿用上一个项目的回执。

卡片分开呈现当前托管配置与历史执行。用户关闭托管后显示“已暂停”，历史 running 回执继续显示真实运行状态。开启只影响之后的新分配，既有 assignment 不自动重新派发；暂停不代表已取消或已完成历史执行。

修复操作分为助理设置、项目规则和接单回执。共享组件只调用宿主提供的处理函数；设计故事使用明确标记的演示反馈。后续生产接入必须把它们绑定到实际入口，并在权限不足时给出可理解的原因。

加载、刷新与失败​

本人卡与负责人摘要遵循相同的读取生命周期：

读取情况展示与操作
首次加载，没有当前上下文的有效快照显示正在同步，不展示其他上下文的事实、回执或操作
同上下文刷新，已有有效快照保留上次确认的事实与历史回执，同时提示正在刷新；不把刷新动作当作新心跳或新接单
刷新失败，已有有效快照保留上次确认的事实，明确提示同步失败、当前显示旧快照，并提供宿主绑定的重试操作
首次读取失败，没有有效快照明确显示同步失败及重试；负责人视图也不能只显示“待同步”
切换项目或存储类型立即移除旧上下文的事实、回执和操作，等待新上下文的数据

重试只调用 onRetry，不自行修改托管、设备或执行状态。未提供处理函数时不显示无效按钮；请求进行中不提供重复重试。宿主还须按用户、项目和数据来源隔离请求及缓存，丢弃已离开上下文的晚到响应。这些展示约束不代替服务端权限校验。

宿主必须提供当前 projectScope: { projectStore, projectId }。本人快照用自身项目字段匹配它；负责人摘要保持两字段 DTO，通过独立的 statusScope 关联响应所属项目。身份不匹配或缺失时不显示响应数据，也不提供旧快照操作。组件不缓存快照；刷新时由宿主继续传入同上下文的上次快照。

设计契约与数据边界​

这是待后端确认的投影契约，不是当前已发布的 API。新 Backend API 的实现应遵守仓库的 Rust 路由归属规则。

字段语义
projectId、projectStore项目标识及 local / cloud 存储类型；相同 ID 不代表相同项目
ownerUserId、roleId本人默认助理的用户与角色标识
enabled、scope当前托管开关和项目 / Tag 覆盖范围
tagMatch、currentTags服务端匹配结果与当前 Issue / 分配上下文的 Tag；无 Issue 上下文时匹配结果保持未知
endpointRef、availability客户端安全的设备引用及心跳投影的可用性，不包含密钥或本地路径
reasonCode、dispatchable不可接单原因与服务端明确给出的是否可派发；客户端不根据开关推测
version、source版本化快照及来源标识；无效或缺失快照显示待同步
receipt、lastReceiptAt绑定真实 human assignment 和 runtime task 的回执；时间统一以回执的 receivedAt 为准

回执必须携带 humanAssignmentId 和 runtime 的设备、任务引用。通知、未绑定的时间戳及客户端操作均不能单独证明已经接单。缺少有效绑定时不显示接单时间。执行结果继续通过 deliveryRef / traceRef 引用；字符串引用本身不证明交付有效，生产服务端仍须验证归属、访问权限与已交付状态。

负责人视图直接消费最小摘要 { dispatchable, availability }，无需读取或传递其他成员的完整本人快照。adapter 对本人及嵌套对象使用字段白名单，丢弃私人提示词、记忆、transcript、认证资料和本地路径。这是展示层的数据最小化；生产环境仍必须在服务端执行权限与跨用户隔离。

原因与执行状态​

原因用户应看见修复入口
not_enabled未开启当前项目托管助理设置
tag_mismatch当前 Tag 不在托管范围项目规则
device_offline执行设备离线助理设置
permission_revoked项目权限已撤销项目规则
execution_failed最近执行失败接单回执

执行状态独立保留 queued、waiting_device、blocked_policy、running、completed、failed。设备可用性未知时不显示在线；原因未知时显示待同步，不制造“暂无数据”或成功结论。completed 没有 deliveryRef 时显示“完成证据待同步”，不得显示成功完成。

公开设计交付​

源码位于 packages/collaboration/src/project-assistant-status/，注册描述位于 packages/collaboration/design-system/project-assistant-status.json。本模块保持独立，不从生产页面调用，也不新增 API、持久化或调度路径。

本范围不包含花名册 CRUD、助理能力匹配或多设备迁移，不自动加入项目，也不自动开启全项目托管。

本地 CSF stories 提供项目和助理两个入口、五种不可接单原因、六种分配状态、暂停与运行并存、缺交付证据、无回执、未知、本人和负责人的首次加载、刷新、失败与重试、负责人摘要、关闭开关、窄屏及主题评审等 30 个状态。所有内容均为合成数据，不读取真实项目或设备。每个状态沿用同一组件结构和共享主题；文案由调用方提供。

完整 Storybook 构建环境留在设计参考仓库，公开仓库提供可导入的 CSF stories，并由既有 collaboration 测试实际渲染它们。组件与契约测试不等同于视觉批准或生产验收。

在仓库根目录运行，命令同样适用于 Windows 终端：

pnpm --filter @wegent/collaboration build
pnpm --filter @wegent/collaboration test src/project-assistant-status

后续验收​

场景预期结果与所需证据
开启并覆盖当前项目两入口使用相同快照，显示托管范围、Tag 匹配、设备可用性和规范接单时间
分配后未启动显示具体原因及有效修复入口；规则命中但助理不可用时仍有可见 assignment
设备离线后恢复服务端先投影 waiting_device；恢复后仅创建一次执行，回执绑定原 human assignment 与 runtime task
关闭后发生新分配项目概览立即显示已暂停，不创建新的默认助理执行；历史记录和正在运行的任务按既有策略保留
负责人读取成员摘要服务端仅返回是否可派发和可用性，不返回私人配置或 transcript
读取与重试本人和负责人区分首次加载、刷新及失败；同上下文刷新保留事实，失败可重试，跨项目或 local/cloud 切换不显示旧数据

生产实现还需验证幂等、权限撤销、Tag / 项目隔离、过期快照与恢复，以及 1440 / 900 / 390 视口、键盘和读屏。真实心跳、调度、服务端 ACL 与完整视口视觉验收均未由本次设计 PR 完成。

宿主接入时由 collab.hostingStatus.v1 控制显示。关闭开关只隐藏状态卡，保留设备设置、assignment 与历史回执。观测应保证规则命中却没有可见不可用原因、无 delivery 却显示完成、跨用户私人数据泄露的次数均为 0。
