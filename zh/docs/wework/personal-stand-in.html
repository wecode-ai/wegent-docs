我的助理与场景角色

在 Issue 中持续协作​

指派 Issue 或在评论中 @ 成员，会唤醒该成员已开启、连接此项目、匹配标签且允许自动处理的助理。 也可以 @ 自己：助理会接收，但不会给自己发送人员提醒。 同一个助理在同一个 Issue 中沿用已有会话；重新指派不会清空历史，也不跳过新的权限核对。 改派、取消指派、删除原提及或暂停自动接收后，仍可继续和重试已有会话，公开回复也会继续同步。 手动启动助理不要求 Issue 指派给自己，也不会自动更改负责人；自动接收配置用于筛选新工作，不限制用户主动操作。项目与 Issue 的实际访问和执行权限仍需有效。 接单和完成结果作为两条独立评论出现。子代理执行期间仍可输入和发送评论，后续唤醒按顺序处理。 直接回复助理评论时不必再次 @，回复会交给该原助理。私人聊天、推理和工具过程不会同步到评论区。

Issue 中的助理回复以“所属用户 (角色)”署名，例如“张三 (助理)”，便于区分不同用户的助理。成员姓名暂不可用时显示用户编号；成员信息加载后显示姓名。

助理聊天与桌面通知​

从 协作 → 我的 可在右侧 助理 标签查看按角色划分的任务列表；点击任务在右侧继续原任务会话。首页只展示 Issue 相关助理任务，助理设置 打开已有配置；通用对话仍从 我的助理 进入。未连接看板时先显示连接引导。首页固定保留助理标签和一个 Issue 详情标签；打开另一个 Issue 会替换当前详情，重新打开仍保留草稿，私人助理聊天不会自动发布到 Issue。

上一条回复结束、或后台结果刚触发新回复时，可以继续发送要求；消息会按当前回合状态送入原会话。

此聊天样式用于“我的助理”的主助理、角色对话：每条原生 AI 消息独立一个气泡，后台执行前的确认语与执行后的结果不会合并。聊天中不显示内部“引导对话”或“执行 X 秒”；普通任务和代码会话的执行过程展示保持不变。

运行时仅对助理身份会话启用原生 subagent v2，以支持可被新消息唤醒的邮箱等待；普通任务保留默认配置，明确配置的 single 协作模式仍禁用子代理，包括恢复已有的 v2 会话。原生权限、来源范围与审批约束保持不变。

从 左侧栏 → 我的助理 打开主助理或场景角色对话。AI 回复使用左侧气泡，你发送的消息在右侧。原生 subagent 在后台执行时，输入框仍可发送下一句话；新消息送入同一个主会话，不停止原子代理，也不等待普通任务队列。发送失败保留内容和附件。待回答问题和权限确认仍通过原卡片处理，聊天消息不会代替授权。独立任务只用于确实需要单独会话、工作区或生命周期的工作，不是保持聊天可用的前提。

桌面端输入框上方的 开启桌面助理通知 提示提供 打开通知设置、不再提示 和 暂时关闭。打开通知设置会进入系统通知设置（macOS、Windows）及 Wework 铃铛的统一设置；请允许系统通知，并检查“助理主动提醒”的系统通知开关。Linux 需自行在桌面环境的通知设置中允许。打开设置不代表权限已经授予。暂时关闭仅作用于当前应用会话；不再提示按账号保存在当前设备，只隐藏提示，不关闭通知。也可随时从顶部 铃铛 → 通知设置 → 助理主动提醒 调整。

我的助理 旁的数字统计主助理及角色对话中的未读 AI 消息，不统计内部 subagent 数量或任务完成次数；超过 99 显示 99+。阅读前台助理对话会清除该对话的未读，后台或隐藏窗口不会自动标为已读。每条新消息最多触发一次桌面通知，点击返回对应设备、账号和助理对话；切换账号不会沿用其他账号的计数。系统拒绝通知时，消息仍保留在会话和通知中心。

角色档案逐项操作​

  1. 左侧栏打开 我的助理，选择主助理或场景角色，点击右上角 助理详情，在浮层底部选择 管理助理。
  2. 编辑职责与偏好。在场景角色设置中直接选择 执行设备，再展开 更多设置（设备、模型、工作区），选择该设备可用的模型和工作目录。不同角色可选择不同设备，保存角色不改变主助理的实例绑定。
  3. 在连接来源中安装/授权应用，选择接收范围及处理方式，保存后才启用。定时事项从该角色连接页的日历/定时交办进入，不是全局云端连接设置。
  4. 在详情浮层的 近期活动 查看工作线程与定时安排。工作在同一浮层只读预览，返回恢复列表位置；需要回复、审批或完整工作区时选择 在工作区打开对话。人工问题仍在统一的 待你处理 和原工作中处理。
  5. 删除场景角色时使用角色设置的删除操作并确认目标。删除与暂停来源不同；保留角色而临时停止接收时应调整来源，不应为了停用而删除角色。

进入助理时，页面先读取引导状态，读取期间显示页内提示。只有确认尚未完成设置后，才自动打开首次引导；已完成设置时直接进入助理。读取失败时可在提示中重试。

首次读取实例绑定期间只显示加载状态，不会提前提示账号不匹配。同一次应用会话内，切换到任务或看板后再返回，保留已加载的助理界面，配置在后台刷新；离开助理时暂停工作列表与配置提案轮询。切换账号或云端服务时不会沿用上一账号的页面数据；只有读取到实际绑定后，才提示是否需要连接原账号。

可以在任务侧边栏打开带 Beta 标识的 我的助理，持续交代工作、追问进展，或请 AI 拟定场景角色。顶部直接展示主助理和已有角色，方便切换。主助理的对话与具体工作的执行记录分别保存；切换角色后返回，可以继续原来的对话。

场景角色负责持续处理一类信息流。主助理和角色都默认打开各自的长期对话，不再切换工作列表页。角色右侧保留 ＋（创建角色） 入口。右上角的详情浮层只保留名称、状态、设备和近期活动，不展示头像和输出内容；近期活动按最近时间混排工作线程和当前角色的定时安排，先显示 4 条，点击 显示更多 每次再展开 4 条。工作在浮层内只读预览，底部的 在工作区打开对话 进入完整会话；定时／监控安排打开居中的任务编辑弹窗，详情浮层保留在其后，关闭后回到原活动位置。

新角色保存后启用；主助理或角色明确新增、启用来源后，也在保存时开始接收，无需再打开第二个接收开关。仅修改名称或职责不会自动恢复暂停的身份；停止整个助理仍须使用原生停止确认，来源授权和操作确认不变。

实例绑定与停止​

打开 我的助理 时，如果版本不兼容，页面先显示错误及升级引导，不会自动切页。点击错误旁的 查看设备情况 进入 云端工作，查看设备状态与版本，并按对应设备支持的方式升级。本机问题可使用桌面端设备区域的 查看本机版本，进入关于页检查更新；该指引不依赖云设备存在。入口本身不会自动安装或重启，处理后返回助理页面点击 重新加载。其他加载错误仍提供重新加载，不显示该设备引导入口。

一个 Wework 实例的主助理保留一个本机或云端绑定。场景角色独立选择运行设备；在角色档案中选择 执行设备并保存后，新任务使用新设备，已有任务、排队工作和同一 Issue 的已有会话继续在原设备处理。主助理绑定不随角色设备变化而改变。角色列表跟随已保存的设备配置，角色历史仍按各任务原来的地址打开。

更换角色设备后需要重新选择模型和工作目录，并确认目标设备上的来源账号和项目可用。系统不会复制凭据、搬移旧任务或重写旧会话。离线设备不可新选；目标保存失败时保留当前草稿。若目标启用结果无法确认，页面要求刷新目标角色，系统不会同时恢复原设备接收新任务。仅更换角色设备无需执行下方的主助理整体停止与换绑流程。

要更换主助理绑定，先选择主助理，再打开 助理详情 → 管理助理，在设置面板左下角点击 停止助理并确认。这会停止当前绑定设备上的接收，并取消该设备上的主助理对话、角色对话、正在执行和排队中的派生任务。其他设备上的角色、其他账号的助理和普通任务不受影响。停止完成后才显示可绑定的本机和云端助理。配置、记忆和历史保留，重新绑定原助理会恢复原有接收开关。

设备离线、取消失败或执行进程尚未确认停止时，保持 停止中，不能换绑。恢复连接后使用 重试停止；关闭并重新打开页面不会解除这一限制。当前绑定设备的设置面板左下角保留 停止助理，其他设备上的角色设置不显示此入口，不再提供重复的接收开关。

停止后也可以迁移：在同一页面选择 迁移档案（主助理或某个场景角色）、目标设备，再点击 迁移并绑定并确认。迁移保留旧档案、记忆和会话历史，在目标追加该档案的职责、模型设置、标签及可见记忆，不覆盖已有配置。副本保持暂停，设备目录、项目/来源授权和安排需要重新配置后启用。复制成功后才换绑；复制失败可重试，旧助理始终保持停止。若换绑后的目标启动确认失败，保留目标绑定以便停止和恢复，不会自动重启旧助理。目标本来就处于停止状态时，也只允许追加这种无设备权限的停用副本，不能借迁移改动原有配置或恢复开关。

首次尚未绑定时，从项目入口打开明确设备上的助理，会按该链接建立首次绑定；已有绑定不会被链接替换。

首次绑定遇到并发版本冲突时，界面读取已保存的权威绑定，不重复绑定或启动助理，也不会覆盖另一个账号的绑定。

在 我的助理 页面点击左侧任务栏的 看板，或在任务视图菜单中选择 看板，会打开个人任务看板。

协作项目顶部的 我的助理 同样带有 Beta 标识，可直接为当前项目配置助理，无需开启实验性功能。

连接 IM 对话​

从左侧栏打开 我的助理，选择主助理或场景角色，再点击右上角 助理详情。在详情浮层中直接点击 钉钉、Telegram、Discord 或微博，打开该渠道的独立连接弹窗。弹窗会显示目标助理及执行设备，只列出当前渠道的私聊；有多个私聊时先选择一个，再点击 连接「助理名称」。成功后显示已连接，点击 完成 回到原详情浮层。连接立即生效，无需进入管理助理或保存资料设置。使用连接功能需要登录云端账号。

若该渠道尚无已登记的私聊，弹窗会说明如何向已配置的机器人发送 /bind，再点击 刷新会话。这一步不会安装机器人或授权平台账号。列表加载失败时可刷新重试；连接保存失败时可重新点击连接。刷新失败会保留已经加载的会话。执行设备离线时另有提示；已连接仅表示路由配置已保存。

IM 私聊默认保留原有的 Wegent 聊天模式；该模式下原有智能体、模型、设备选择和新建对话命令照常使用。发送 /standin（或 /mode standin）进入 Wework 助理模式；发送 /chat（或 /mode chat）返回 Wegent。/mode 查看当前模式。助理模式未显式指定身份时，使用账号默认执行设备的主助理。未配置默认设备、设备离线或所连接的角色已删除时，IM 会提示打开助理详情浮层检查连接；不会自动选择其他设备或角色。要将同一 IM 私聊改绑到其他角色，切换到目标角色，在其详情浮层中打开相同渠道、选择私聊并确认连接。

新消息进入该助理已有的长期对话。旧的 task 模式迁为助理模式，旧的 IM 任务绑定会解除，旧任务和对话历史保留；任务页不再提供“继续到私聊”。在助理模式中引用任务通知或追问任务卡片时，所引用任务仅作为当前助理的资料，不会改变助理绑定或模型。任务通知的订阅与通知渠道仍在通知设置中分别管理。

手动设置与对话调整​

在助理档案中维护职责和共享偏好，在角色档案中维护角色职责及连接来源。偏好可以随时修改或删除。修改设置后需要保存；未保存的设置不会启用新的来源。

也可以在对话中描述需要的角色或职责调整。AI 生成变更提案后，确认卡直接显示在当前会话中，列出受影响的角色、来源范围和处理方式。检查后点击 确认并应用 才会保存并生效；成功后，会话显示 配置已应用 及实际变更，失败则保留确认卡和错误提示。角色的新增群保存到该角色的连接中，不会同时扩大主助理的来源范围，可切换到对应角色的设置查看。也可以从 助理详情 → 待确认配置 打开同一提案；关闭弹窗不代表确认或拒绝，卡片仍在会话中。可以继续追问、调整提案，或选择 暂不应用。设置已被其他操作修改时，旧提案不能覆盖新设置。

主界面保留对话、输入框、角色切换及角色右侧的 ＋，右上角保留 助理详情 入口。连接或运行异常收成一行提示，点击进入 连接与运行状态 查看完整记录或重试。详情浮层右上角的问号图标打开 使用示例，近期活动标题旁的箭头打开全部活动；设置页直接显示 记忆 入口，不再堆叠这些入口。停止操作独立放在设置面板左下角。设置主页面、连接页面、来源详情都有明确入口和返回上级按钮；页头 设置层级 路径可直接返回设置或连接，不会绕开未保存内容的确认。后台主动更新使用独立标识，不显示为你发送的消息。

后台主动提醒​

所有已连接来源共用提醒判断：与你相关的重要信息、紧急事项，或有具体证据支持的进度可能异常，都可以主动提醒，不要求一定需要你采取行动。提醒说明发生了什么、为什么现在值得关注、来源与时间，并区分已知事实、推断和不确定性。进度异常不要求已经确诊，但要能结合已知预期说明风险信号；仅仅缺少更新、旧问题的当前状态未知，或消息自称紧急，不足以触发提醒。已解决或被新状态替代的问题不能当作当前风险重复播报，重要的新里程碑或结果仍可提醒。

同一事项的相关事件合并判断，参考近期已发提醒跨批次避免重复；只有新增证据改变重要程度、紧急程度、进度判断或应对方式，才再次提醒。普通状态变化和重复投递保持安静，不为制造提醒而扩权或新建核实任务。有来源主题标识时一并保留账号和来源用于关联；缺少标识时不编造，以已有证据作语义判断。这是模型判断策略，不是实时状态的独立校验保证。你明确要求的报告、提醒、定时安排和已授权工作的执行仍沿用原流程，不会因此被静默忽略。

查看、编辑和遗忘助理记忆​

主助理记忆面板的“遗忘规则”也列出尚未关联新规则的“旧版遗忘指纹”，显示遗忘时间和指纹短标识。旧版没有保留事实原文或作用域，因此显示“作用域未知”，不会推测或恢复内容，也不会提供给模型或显示在项目专属面板中。选择“删除规则”并确认仅移除该指纹；一条旧记忆可能有多个指纹，其他限制保持不变。仍被新规则引用的指纹不能单独删除；并发变更需重新加载后再操作。

从 左侧栏 → 我的助理 → 助理详情 → 管理助理 → 记忆 打开记忆面板，先确认当前执行设备。

不必每次说“记住这个”。助理可以从当前已授权的正常对话中提取有持续价值的信息，例如稳定偏好、反复出现的约束、长期目标和可复用的决定。引用、假设、助手建议及其他人的事实不能直接变成关于你的记忆；来源内容也不能授予新的权限。

记忆搜索按响应大小分页；单条记录过长时会分块读取，不会因此跳过该条或挡住后续记忆。续读期间记录或可见范围变化，需要重新搜索，不能把旧页与新页拼成同一条证据。

会话历史整理读取用户和助手的可见文本，不直接收集工具调用的原始输出、运行过程或隐藏推理。本次自动整理仅覆盖已授权会话文本；只在工具输出中出现、且没有其他可验证来源的信息，目前不属于完整覆盖范围，不能将“会话文本已读完”理解为所有工具结果均已整理。

暂停助理或角色接收新工作，不会撤销已保存的来源授权，这些信息仍可参与记忆。要停止整理，请暂停记忆整理安排；要撤销某个来源，请移除其授权。自动整理仅开放经来源与运行身份校验的记忆读写和进度工具，不开放 Shell 或外部写操作。

记忆整理任务默认不显示在左侧任务栏，包括运行中和已结束的记录。可从 我的助理 → 设置 → 连接 → 日历 → 助理记忆整理 查看运行记录并打开原任务；隐藏不影响后台整理或历史记录保存。

启用主助理后，执行设备会自动创建一次 助理记忆整理 安排，默认每 6 小时检查一次。可从 我的助理 → 设置 → 连接 → 日历 → 助理记忆整理 查看周期和运行记录，并暂停、修改或删除。已暂停或删除的安排不会被后台自动重建。整理使用独立会话，不占用当前对话；执行设备和模型必须可用。完成后可从运行记录打开原任务查看结果；整理不会为了回报结果而自动启动具有普通工具权限的主助理对话。

后台整理保留原文证据和作用域，按分页读取会话及长消息。尚未读完或保存失败的会话不会推进完成进度。纠正或遗忘后，后台整理不会从同一旧证据重建该条记忆；遗忘不会删除原始会话。同时按用户选择保留最小化遗忘规则，记录被排除的简短事实及作用域，不保留原始对话、文件或证据摘录。规则不是有效记忆；助理读取规则后，应按含义避免重新学习同一事实，但不能把同一主题下的新事实一并排除。精确指纹由程序校验，跨表述的语义判断由模型执行，尚不能据此承诺识别所有语义相同的内容。可在记忆面板下方展开“遗忘规则”，查看简短事实及作用域；选择“删除规则”并确认后，后续整理允许重新学习，取消不生效。删除规则不会立即恢复有效记忆，也不会影响其他规则。读取或删除失败时保留已有数据，并提供单独的重新加载入口。真实模型的跨表述语义效果仍需持续验证。

有保存原文证据的记录会显示 查看来源证据。展开可查看证据片段、来源标识，以及它是用户原话、助手原话还是来源记录。助手原话不代表用户事实。没有保存证据的记录不显示此入口；展开证据不会重新读取来源或修改记忆。

在面板中修改内容或作用域后，旧原文不再作为新记忆的证据展示；后台重新取得相符证据时可补齐。仅打开记录或不改内容地保存不会清除已有证据。

模型选择​

助理档案的模型选择支持云端模型和执行设备上的本地自定义模型。云端模型使用执行设备连接的 Wework 云端账号；本地自定义模型使用该设备的 provider 配置和认证。助理创建的具体工作沿用已保存的模型选择。切换执行设备后，请确认该设备具有对应模型的配置和访问权限。

助理聊天默认继承档案中已保存的模型和思考档位，也可在聊天内临时选择。下次保存的模型或档位有实际变化时，已有聊天从下一条消息重新继承新设置，当前执行回合不会重启。档案改动不会改变已有工作任务的工作目录或会话。

临时换模型时，使用主助理或角色聊天输入框的模型选择器。首次发送前直接生效；支持按会话路由的执行设备可在原会话切换 Provider，保留原会话标识、历史和草稿。旧设备跨 Provider 切换时需要确认，下一条消息会在当前助理聊天中开启新会话，历史消息和草稿仍可查看。当前工作结束后才能跨 Provider 发送。临时选择不修改已保存的档案或普通聊天。

助理聊天目前仅支持具备操作审批能力的 Codex 运行时，暂不支持 Claude Code 运行时。已保存的 Claude Code 模型不会自动替换；可在聊天输入框的模型选择器中手动选择可用的 Codex 模型后继续。普通工作任务中的 Claude Code 行为保持不变。

连接钉钉和协作项目​

连接页按来源展示 已配置 和 可添加，同一来源的群聊、邮箱或项目合并为一行；其他来源入口始终可见。每行显示接收范围、当前状态和下一步操作。已有范围不代表正在接收：协作项目未开启接收时仍保留范围摘要，并标明 未开启接收。日历位于独立的 定时交办 区域。

可以在顶部按应用名称或已配置的范围名称搜索，或点击 已配置 只看已有来源；点击 全部来源 恢复完整目录。计数按来源计算，筛选不会改变助理的配置。

进入来源详情后，按提示安装插件或登录，再选择接收范围和处理方式。在远程执行设备上运行的来源需要到该设备完成授权。来源暂不可用时，仍可查看并移除已有接收范围。修改范围或处理方式后，页面提示保存后生效；邮箱账号验证成功也需要保存助理设置才会开始接收新邮件。

在档案的连接来源中选择钉钉，默认接收所选账号可访问的全部群聊提及和联系人单聊，包括以后新增的群和联系人。也可以切换到筛选来源，搜索并批量选择具体群或联系人。每个连接绑定选择时的钉钉账号，不会因为切换当前账号而自动改绑。需要插件安装或登录时，先完成对应步骤，再选择来源。

从 左侧栏 → 我的助理 → 选择主助理或角色 → 助理详情 → 管理助理 → 连接 → 钉钉 进入来源设置。在筛选来源中添加具体群后，该群旁的 接收消息 可以选择 仅接收 @我（默认）或 接收全部消息；已有的具体群也可以直接修改。所有群聊的统一订阅仍只接收 @我，私聊没有此选项。修改后点击设置面板的 保存 才生效；取消不保存。切换范围后从保存生效时开始接收，不补收此前的历史消息。接收全部消息不代表每条都回复，仍由助理职责、处理方式和发送确认策略决定如何处理。

群中手动发送的“自己 @ 自己”也可以交办工作。在筛选来源中明确选择自己作为私聊联系人并保存后，也可以在与自己的私聊中手动发消息交办助理；仍遵循该来源的处理方式和操作确认策略。仅开启“所有联系人私聊”不会启用这一入口，发给其他联系人的本人消息也不会被当作指令。助理发出的回复始终保留钉钉 AI 代发标记。

钉钉来源采集统一忽略钉钉明确标记为机器人发送或带有 AI 代发标记的消息，不限发送者，避免 Wegent 对话机器人的任务通知再次触发助理并形成循环。其他机器人的业务消息同样不会自动触发处理。人工转发通知或引用通知提问仍可进入处理；历史消息查询仍保留这些通知供理解上下文。

每个来源可分别设置为手动交办、操作前询问，或自动处理。新钉钉连接默认在操作前询问。接入使用执行设备上已安装的钉钉插件及其账号；需要登录时，通过原有钉钉连接入口完成授权。

进入 我的助理 → 助理详情 → 管理助理 → 连接 → 来源详情 → 处理方式，“处理方式”默认折叠，点击展开后，三个设置使用相同的开关；保存助理设置后生效：

  • 收到后立即处理：开启时收到事件后开始处理；关闭时先汇总新事件，再由助理判断如何处理。角色的新连接默认开启，主助理的新连接默认关闭。此设置不决定会话归属，也不跳过操作确认。
  • 每次新建会话：默认关闭，继续这个来源的同一会话；开启后，每个新事件各用一个独立会话。关闭时，同一角色、同一账号下的同一具体来源使用同一会话，不同群聊、联系人或来源不混用。“全部范围”内的不同具体来源也不合并。明确回复已有工作仍返回原会话，重复投递不会再建会话。

立即处理和每次新建会话可以分别开启或关闭，互不影响。已有工作与消息归属不因修改设置而重组。复用目标正在等待你的回答或审批时，新事件保持待处理；已归档的目标须先在 近期活动旁的箭头 → 全部活动 → 对应工作 → 取消归档 显式恢复，恢复本身不会启动执行。后台仅派发本次选中的消息，不带上此前忽略或延后的消息。协作项目按 Issue 保持独立会话，不跨 Issue 合并；定时交办沿用每项安排的既有会话模式。钉钉来源的 发送前逐次确认 单独一行显示，仍通过原有确认流程管理授权。

直接处理不要求先填写职责或偏好。只有一个符合条件的接手角色时，后台统筹的历史失败或待答问题不应阻塞该来源的直接派发；原有问题和失败仍保留，不能因此自动回答审批或重放执行结果不明的命令。后台统筹重试会按实际会话和执行回执恢复，而不是仅凭已有任务记录尝试续聊。

协作项目沿用项目成员权限，项目专属智能体不能扩展接收其他项目或钉钉来源。多个角色都能接手同一来源时，由 AI 选择一个处理角色，避免重复执行。

已连接的协作项目显示项目名称，包括有项目访问权限但未加入其所属空间的项目。切换助理执行设备后，已连接项目的名称仍保留，也可以解除连接；只有在当前设备执行时，才能新增本地项目连接。

远程执行设备仍可使用“所有项目”范围，该范围使用所选执行器自己的项目目录，不会把当前电脑未显式连接的本地项目作为远程连接展示。

工作归属和操作确认​

执行方式按任务需要选择：简单或紧密关联的工作可在主助理直接完成；内部拆解可使用已有权限允许的 subagent；只有需要独立会话、工作区或长期追踪时才创建工作 thread。“发布新版本时通知我”等未来条件请求使用原生定时／监控安排，不用一次性 thread 或常驻 subagent 替代。安排必须经过现有确认并成功保存后才算生效。选择执行方式不改变来源权限、登录授权或操作确认。

新事件按来源的会话策略归属，不再由模型根据文本相似度自动合并。明确回复已有工作的消息保留原会话。在工作预览中展开关联消息，可以拆成独立工作，或移到同一角色的其他工作；调整归属不会重新执行已处理的消息。

需要确认的操作统一出现在 待你处理，从这里进入原会话的审批卡确认或拒绝，无需手动发送“是”。发送钉钉回复时，确认卡展示与该工具调用绑定的待发送正文。选择操作前询问时，写入文件、执行需要提升权限的命令和具有写入性质的 MCP 工具调用使用运行时确认机制。确认只针对当前操作，不提供长期放行规则。该策略目前要求使用 Codex 运行时。

统一处理人工判断​

助理和普通任务提出的结构化问题共用同一条待处理事项。应用在前台时，通过右上角轻提醒发现问题；简单问题可以展开后直接回复。右上角通知铃铛中的 待你处理 打开同名页签，查看对应的原任务或 Issue，并在原界面处理。工作列表和通知条目不再各自提供独立回复表单。

待你处理顶部完整展示所选通知的原问题，并保留实体名称；窄屏隐藏列表后仍可直接阅读问题。待你处理是原实体的容器：任务定位到所选问题的原会话轮次，并展示对应的原生输入卡；Issue 展示已有 Issue 界面，并通过原执行和消息 ID 定位提出问题的 AI 消息及上下文，而非线程起始留言。打开通知时保留阅读位置，主动点击回复后才聚焦输入框。上下文、问题、表单、审批和授权均由原界面展示和处理，不额外抽取或总结对话，不另建回复表单。

容器顶部的 在原界面中打开 返回对应任务或 Issue，并保留源评论定位。需要完整工作区的文件、Review、计划和执行详情操作跳转到原任务；子 Issue 打开对应的原详情，不在待你处理内叠加工作区侧栏。

原任务即使未出现在侧栏列表中，打开后也会恢复它的标题、模型和工作区，支持继续对话。打开原任务不会改变侧栏原有的显示范围。

应用在后台时，按通知设置使用系统通知；支持文字回复的简单异步问题可通过系统通知回复。通知渠道在右上角铃铛的设置中统一管理，账号区域不再保留重复的全局 IM 通知菜单。系统通知还受操作系统权限和通知设置影响。

阅读通知、关闭提醒或标为已读不会完成待办。只有回复被接收或原问题已处理，事项才移入历史；发送失败会保留草稿。设备离线时保留上次已知的问题和草稿，重新连接并核对问题后才能回复。执行审批、连接器登录和复杂表单仍在原上下文处理，普通业务回答不能授予操作权限。Issue 问题的回复写入原评论线程后继续对应执行。

需要停止时，使用设置面板左下角的 停止助理并确认。来源读取或启动失败会显示错误，可在修正登录、模型或来源设置后重试。执行器保存消息游标、去重记录和归属信息；重启后不会把已经接收的消息当作新消息重复处理。

采集来源时，执行器读取超时会自动退避重试，不需要重新保存连接；此前因该超时停住的来源也会从原游标恢复。自动恢复只针对读取，不会自动重放发送等操作；登录失效、权限拒绝或响应格式错误仍需修正原因后重试。

Issue 的人工介入闭环​

Issue 卡片在标题上方已有的编号／状态行右侧，用图标区分智能体处理、助理处理和等人；等人使用人物叠加小钟图标，旁边只显示主体名字，悬停提示“等待某人处理”，不增加独立一行。执行状态确认正在运行时显示对应智能体或助理；有待回复的问题时优先显示接收人。没有运行中的 AI 时由指定的人处理，未指定则由 Issue 创建人接手，不显示“待分派”等第三种处理状态。排队、失败和离线等详情仍在执行详情中展示，业务状态保持独立。

AI 在绑定的 Issue 执行中提出结构化异步问题后，问题会保存到 Issue，包含原线程、执行身份和处理记录。责任人或协作小组负责人负责把问题分给具体的人；尚未指定接收人时仍由责任人承接，没有指定责任人则由创建人承接，不广播，也不自动选择协调人。AI 使用 list_human_requests 查询问题，原提问执行可通过 set_human_request_blocking 明确标记是否有步骤依赖答案；此操作不转派、不重置等待时间，也不会授予分派权限。责任人使用 assign_human_request 指定处理人。

接收人通过统一的“待你处理”和原 Issue 的问题卡作答。定向通知沿用协作通知设置及已配置的通知渠道。回答写入原评论线程，并交回原执行，不授予对方私人会话或设备的访问权限。读通知不等于处理完成；回答仅排队时仍显示等待接收，原执行接收后才解除对应标记。多个问题分别结算，仍有未解决的问题时继续显示“等人处理”。AI 只等待依赖答案的步骤，其他工作继续。

云端上报问题和源执行修改阻塞标记，需要原活动具备可验证的执行记录，准确关联项目、Issue、Runtime、设备及执行所有者。仅有手工任务绑定，或小组活动尚无匹配的执行证据时，会返回冲突（409），不能仅凭同名设备或推测 owner 继续；应先恢复原执行的可信记录。本地项目仍使用所属执行器的原生来源校验。

看板视图设置提供“仅显示待我处理”，按当前查看者匹配，而不是保存视图的人。离线时保留上次问题和草稿，恢复连接后再校验处理权限。执行审批、登录授权继续使用原生流程，业务回答不能代替授权。

项目看板工具栏还提供一键“待我处理”，它只影响当前查看，不会改写保存视图。全局“待你处理”包含原生项目中轮到自己的事项，以及明确向自己提出的项目问题；同一问题不会同时作为普通事项重复出现。选择项目事项后，在原有双栏内打开真实 Issue 详情，不创建虚构的运行任务。

等待时长与流程分析​

“在你这里”从本轮交接给当前处理人的时点计算，转派给另一个人后重新起算。仅修改问题、阻塞说明、读取通知或保存回答不会重置时钟。普通事项从明确的人类分配、创建人首次接手或本轮 AI 执行结束的可靠时点计算；缺少本轮交接证据的历史记录显示“交接时间未记录”，不用更新时间冒充交接时间。时间按 UTC 保存，界面按自然经过时间展示，不等同于工作日内耗时。

问题保留提出、分派、回复、拒绝送达和执行接收等业务事件，包括事件时间、认证主体、接收人变更和原消息身份，不复制答案正文。以后可按这些证据统计等待分布、跨人交接和成功接续；认证主体不证明实际操作者一定是本人，也不能仅按等待长短、转派次数或回复字数断定个人表现。分析仍须遵循原项目权限，并区分审批职责、外部依赖、AI 执行时间、非工作时间和缺失证据。当前记录是可追溯的业务数据，不是防篡改的人事审计系统；本功能不自动给人贴“瓶颈”或“不干活”等标签。

Issue 分配接收回执​

协作通知会读取本机及支持远程查询的在线执行设备上的助理处理记录。查询失败时，提示会标明失败设备及原因；这表示处理记录未能加载，并不代表 Issue 执行失败。若提示版本不兼容，请更新该执行设备的 Executor，并刷新通知。其他桌面 App 设备不参与远程查询；本机记录仍通过本机执行器读取。

Issue 详情的负责人下拉控件旁用图标显示本次分配的接收情况：白色人形带勾表示本人已读，黑色人形带勾表示助理已接收；悬停可查看状态和时间。同一 Issue、同一负责人的详情刷新期间，顶部保留已显示的回执，避免中断悬停提示；切换 Issue 或负责人时不显示上一范围的回执。本人成功打开详情后记录已读；助理成功接下任务、准备处理后记录接收，无需等待执行完成。两个回执和各自时间独立保留，不会将 Issue 标为完成。通知预览、全部标为已读和后台读取不产生本人已读回执。

分配人和接收人均可查看回执，详情打开期间会自动刷新。底部分配动态中的最近一次有效分配也显示同一份回执，与顶部负责人控件同步更新，不为历史动态增加轮询。转派后回执只显示在最新分配动态上，取消分配后不再显示旧接收人的回执。转派或重新分配后重新记录；历史分配没有可靠回执时，图标提示“暂无接收记录”。云端回执同步失败会在执行器本地保留并补报，失败后逐步延长重试间隔，最长每小时一次；待发送回执最多保留 30 天。重启不会重置等待时间。本地项目回执保存在所属执行器。

Issue 状态或其他属性刷新不会重建同一次指派的回执图标或中断其悬停提示。重新指派（包括再次指派给同一个人）会立即隐藏旧回执，等待本次指派的结果。

助理接收分配时先保存本人设备上的任务绑定和接收回执，再启动执行；交给后台助理安排的事项在进入待处理队列时即记录接收。接收不代表执行成功，之后启动失败也不会撤销已接收的事实。云端上报仍检查当前分配、本人设备和任务绑定；拒绝原因写入诊断日志，不通过放宽权限补写回执。

云端分配的启动意图保存在所属执行器。偶发云端请求失败后，执行器按退避间隔自动恢复，重启后继续；已有绑定但尚未创建本地任务时，恢复同一个任务，不依赖删除绑定成功。恢复前重新核对服务、账号、当前分配、角色和设备，转派或断开项目后不执行旧分配。已被本地执行器接收的任务不会因启动补偿而重复执行；模型执行失败仍通过原任务的重试入口处理，配置错误需要人工修正。

通知尚未成功交给执行器时，桌面会退避重试，而不是将失败的投递当作已处理。执行器重启并报告云端连接未配置后，桌面按当前登录态重新配置连接和连接器授权；普通网络断连仍由执行器原有的重连机制处理。

日历安排与项目负责人​

项目负责人对话和自动处理​

打开 设置 → 通用 → 实验性功能 后，在协作项目中使用 负责人对话。这是现有协作小组负责人的条件入口，不是旧版独立“项目 AI 管理者”页面。

操作步骤与边界
选择小组和设备打开负责人对话，选择当前项目协作小组及设备；没有小组时点设置小组与负责人
与负责人沟通智能体负责人可在私人输入框讨论目标与进展；人工负责人按提示回到原 Issue 协作
工作列表 / 设置用顶部工作列表回到具体事项，或用设置调整小组配置；具体执行仍关联原 Issue
记忆从负责人对话顶部进入记忆；此面板固定当前项目作用域，不会把私人记忆发布到项目
发布到项目顶部发布到项目 → 选择有评论权限的目标 Issue → 填写要公开的指令或结论 → 发布；成功后返回私人对话
让负责人自动处理在支持的智能体负责人及设备下开启；按原项目权限和操作确认处理共享项目事件
接管 / 停止接管前核对原成员与设备并确认；原绑定停止后续派发，已开始工作保留原执行状态；停止不等于删除 Issue
现在查看当前由自己处理时手动触发检查，阅读处理状态或到原 Issue 补充信息；检查成功不代表所有工作完成

发布只共享你填写的内容，不附带私人聊天或记忆；没有可评论的 Issue 时返回项目创建或选择可访问的 Issue。等待权限检查或提交期间按钮可能不可用，不通过换设备绕过权限。

在 我的助理 → 角色档案 → 连接 → 日历 / 定时交办 中记录事项和触发时间，支持一次或周期性触发。到时将事项交给所属助理处理，沿用助理当时的职责、设备、模型和工作目录；整个日历连接统一设置处理方式。日历事项单独保存，返回或关闭时保护未保存的修改；运行记录可进入对应工作查看结果。

新建周期安排默认使用当前设备时区，已有安排保留保存的时区。需要指定其他时区时，在编辑页展开 频率右侧齿轮（频率设置）→ 时区，填写 IANA 名称（例如 America/New_York）并保存。任务侧边栏的 已安排 → 对应任务 也使用同一入口。仅一次的执行时间仍按当前设备本地时间填写。

通过对话交办未来执行时，助理应先查阅已有工作证据，或立即委派只读检查，核实实际流程、工作目录及必要输入。可以从说明和配置中查到的信息不应反复要求你填写；确实缺少业务选择时，通过问题卡确认，未解决前不创建自动执行安排。要求“走现有自动流程”不代表流程已经核实，也不能把“到时再研究怎么做”当作准备完成。

这里的“只读检查”是预查任务的行为要求，不是新增的沙箱或工具权限模式，也不保证预查任务在技术上无法写入。预查沿用既有权限契约、联网能力和工具审批规则；本轮仅约束调度决策，不扩大或收紧已有权限。

执行方案应写入日程说明，保留原要求，不擅自改成提醒。明确要求提醒时，只需确认提醒内容和时间，不需要检查被提醒事项的执行流程。创建成功仅表示安排已保存，不保证指定时间前完成，也不提前批准发布等外部操作；执行时仍需遵循原生权限、审批和必要条件检查。

任务侧边栏的 已安排是独立功能，保留原有的目标、运行任务、模型和执行环境设置，无需开启实验性功能。它与连接日历分别管理各自的列表、编辑和运行记录。助理工作列表展示具体工作。

项目页面中的负责人就是原协作小组负责人。对话顶部展示小组与负责人姓名，设置仍使用原小组配置。“自动处理项目事件”是在选定设备上启用该负责人的持续处理能力；每个项目与小组只有一个有效成员／设备绑定，切换必须显式接管。私人聊天与记忆仅自己可见，明确发布后才进入所选 Issue。

连接 GitHub 和 GitLab​

角色可接收个人事件或仓库全部可订阅事件。插件提供能力，角色设定决定如何处理。仓库 Webhook 由云端暂存，执行设备离线期间不运行；外部写入保留逐次原生确认。详见 GitHub 与 GitLab 连接。

首次使用助理​

首次打开“我的助理”时，先连接常用应用，再确认开始使用。连接步骤复用助理设置中的项目、钉钉、邮箱等入口，按提示授权并选择关注范围。也可以不连接任何应用，直接点击“继续”。

下一步会列出已选择的内容。点击“开始使用”后保存连接并开启主助理；没有连接时也能正常开始聊天，只是暂时没有应用动态可供分析。以后可以随时在助理设置中添加连接。关闭引导不会保存连接草稿；有修改时会先询问是否放弃。账号授权仍通过原有登录流程完成。

引导不会自动创建定时任务。顶部问号提供每日简报、会议准备、项目跟进、钉钉回复和每周复盘等示例；选择后只填入对话草稿，发送后再确认资料范围和定时安排。

每周复盘可以在对话中交办，或通过 助理设置 → 连接 → 日历 的模板创建。默认时间为每周一北京时间 09:00，回顾本设备上此前七天的工作与对话。可以编辑、暂停或删除，删除后不会自动恢复。
