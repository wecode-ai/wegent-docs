我的分身与场景角色

角色档案逐项操作​

  1. 左侧栏打开 我的分身，选择主分身或场景角色，再打开其档案/设置。
  2. 编辑职责与偏好；展开 更多设置（设备、模型、工作区），查看绑定设备，选择可用模型和工作目录。需要其他设备时，先按下方“实例绑定与停止”流程停止并换绑，再检查模型与来源账号。
  3. 在连接来源中安装/授权应用，选择接收范围及处理方式，保存后才启用。定时事项从该角色连接页的日历/定时交办进入，不是全局云端连接设置。
  4. 通过工作列表看执行事项，通过 待你处理 回答人工判断，通过 需要检查 查看异常；这三者不是同一个列表。
  5. 删除场景角色时使用角色设置的删除操作并确认目标。删除与暂停来源不同；保留角色而临时停止接收时应调整来源，不应为了停用而删除角色。

进入分身时，页面先读取引导状态，读取期间显示页内提示。只有确认尚未完成设置后，才自动打开首次引导；已完成设置时直接进入分身。读取失败时可在提示中重试。

首次读取实例绑定期间只显示加载状态，不会提前提示账号不匹配。同一次应用会话内，切换到任务或看板后再返回，保留已加载的分身界面，配置在后台刷新；离开分身时暂停工作列表与配置提案轮询。切换账号或云端服务时不会沿用上一账号的页面数据；只有读取到实际绑定后，才提示是否需要连接原账号。

可以在任务侧边栏打开带 Beta 标识的 我的分身，持续交代工作、追问进展，或请 AI 拟定场景角色。顶部直接展示主分身和已有角色，方便切换。主分身的对话与具体工作的执行记录分别保存；切换角色后返回，可以继续原来的对话。

场景角色负责持续处理一类信息流。打开角色时先看到工作列表；点击一条工作可在右侧查看预览，需要人工判断时进入统一的 待你处理，需要完整上下文时进入具体工作。角色也有独立的长期对话入口。

实例绑定与停止​

一个 Wework 实例同时只能绑定一个分身，可以是本机或云端分身；场景角色属于该分身，不是另一个实例绑定。页面和设置中不提供直接切换执行设备的选择框，重新打开页面、设备列表变化或切换账号也不会替换当前绑定。

要换绑，在页头点击 停止分身并确认。这会停止整个分身的接收，并取消其主分身对话、角色对话、正在执行和排队中的派生任务，不影响其他账号的分身或普通任务。停止完成后才显示可绑定的本机和云端分身。配置、记忆和历史保留，重新绑定原分身会恢复原有接收开关。

设备离线、取消失败或执行进程尚未确认停止时，保持 停止中，不能换绑。恢复连接后使用 重试停止；关闭并重新打开页面不会解除这一限制。停止分身与仅关闭 接收新工作不同，后者不取消已有工作。

停止后也可以迁移：在同一页面选择 迁移档案（主分身或某个场景角色）、目标设备，再点击 迁移并绑定并确认。迁移保留旧档案、记忆和会话历史，在目标追加该档案的职责、模型设置、标签及可见记忆，不覆盖已有配置。副本保持暂停，设备目录、项目/来源授权和安排需要重新配置后启用。复制成功后才换绑；复制失败可重试，旧分身始终保持停止。若换绑后的目标启动确认失败，保留目标绑定以便停止和恢复，不会自动重启旧分身。目标本来就处于停止状态时，也只允许追加这种无设备权限的停用副本，不能借迁移改动原有配置或恢复开关。

首次尚未绑定时，从项目入口打开明确设备上的分身，会按该链接建立首次绑定；已有绑定不会被链接替换。

首次绑定遇到并发版本冲突时，界面读取已保存的权威绑定，不重复绑定或启动分身，也不会覆盖另一个账号的绑定。

在 我的分身 页面点击左侧任务栏的 看板，或在任务视图菜单中选择 看板，会打开个人任务看板。

协作项目顶部的 我的分身 同样带有 Beta 标识，可直接为当前项目配置分身，无需开启实验性功能。

手动设置与对话调整​

在分身档案中维护职责和共享偏好，在角色档案中维护角色职责及连接来源。偏好可以随时修改或删除。修改设置后需要保存；未保存的设置不会启用新的来源。

也可以在对话中描述需要的角色或职责调整。AI 生成变更提案后，点击顶部 待确认配置 查看角色、来源范围和处理方式。检查后点击 确认并应用 才会生效；关闭弹窗仅收起提案，不会确认或拒绝。也可以继续追问、调整提案，或选择暂不应用。设置已被其他操作修改时，旧提案不能覆盖新设置。

主会话保持对话与输入框。工作列表入口显示待处理数量，点击后查看具体事项；连接问题和非阻塞的后台异常统一收在 需要检查 中，展开后可查看记录或重试。后台主动更新使用独立标识，不显示为你发送的消息。

查看、编辑和遗忘分身记忆​

从 左侧栏 → 我的分身 → 记忆 打开记忆面板，先确认当前执行设备。

操作具体步骤与边界
添加记忆点击添加，填写内容并选择作用域，再保存；空白内容不能保存，单条最多 1000 字符
选择作用域个人记忆、已有角色及已连接来源按当前配置列出；项目专属面板会固定项目作用域，不能任意跨作用域保存
编辑在记录上点击编辑，修改后保存；不是修改输入框草稿
取消或关闭有未保存修改时先确认是否放弃，不会因关闭面板自动保存
遗忘在对应记录选择遗忘，再确认；取消则保留记录。遗忘不是归档对话，也不删除原始消息或项目
错误恢复查看面板内错误并重试；作用域已断开或不存在时，先恢复来源/角色或选择有效作用域，不会静默改存到个人记忆

模型选择​

分身档案的模型选择支持云端模型和执行设备上的本地自定义模型。云端模型使用执行设备连接的 Wework 云端账号；本地自定义模型使用该设备的 provider 配置和认证。主分身对话与它创建的具体工作都沿用已保存的模型选择。切换执行设备后，请确认该设备具有对应模型的配置和访问权限。

连接钉钉和协作项目​

连接页按来源展示 已配置 和 可添加，同一来源的群聊、邮箱或项目合并为一行；其他来源入口始终可见。每行显示接收范围、当前状态和下一步操作。已有范围不代表正在接收：协作项目未开启接收时仍保留范围摘要，并标明 未开启接收。日历位于独立的 定时交办 区域。

可以在顶部按应用名称或已配置的范围名称搜索，或点击 已配置 只看已有来源；点击 全部来源 恢复完整目录。计数按来源计算，筛选不会改变分身的配置。

进入来源详情后，按提示安装插件或登录，再选择接收范围和处理方式。在远程执行设备上运行的来源需要到该设备完成授权。来源暂不可用时，仍可查看并移除已有接收范围。修改范围或处理方式后，页面提示保存后生效；邮箱账号验证成功也需要保存分身设置才会开始接收新邮件。

在档案的连接来源中选择钉钉，默认接收所选账号可访问的全部群聊提及和联系人单聊，包括以后新增的群和联系人。也可以切换到筛选来源，搜索并批量选择具体群或联系人。每个连接绑定选择时的钉钉账号，不会因为切换当前账号而自动改绑。需要插件安装或登录时，先完成对应步骤，再选择来源。

群中手动发送的“自己 @ 自己”也可以交办工作。在筛选来源中明确选择自己作为私聊联系人并保存后，也可以在与自己的私聊中手动发消息交办分身；仍遵循该来源的处理方式和操作确认策略。仅开启“所有联系人私聊”不会启用这一入口，发给其他联系人的本人消息也不会被当作指令。分身发出的回复始终保留钉钉 AI 代发标记，并根据钉钉返回的标记过滤本人 AI 消息，避免自动回复触发自身。

每个来源可分别设置为手动交办、操作前询问，或自动处理。新钉钉连接默认在操作前询问。接入使用执行设备上已安装的钉钉插件及其账号；需要登录时，通过原有钉钉连接入口完成授权。

协作项目、日历和钉钉的 处理方式统一提供 直接处理选项。开启后，收到事项会直接创建对话处理；关闭后，由后台分身判断如何处理。角色的新连接默认开启直接处理。操作确认仍按连接策略执行。

协作项目沿用项目成员权限，项目专属智能体不能扩展接收其他项目或钉钉来源。多个角色都能接手同一来源时，由 AI 选择一个处理角色，避免重复执行。

已连接的协作项目显示项目名称，包括有项目访问权限但未加入其所属空间的项目。切换分身执行设备后，已连接项目的名称仍保留，也可以解除连接；只有在当前设备执行时，才能新增本地项目连接。

远程执行设备仍可使用“所有项目”范围，该范围使用所选执行器自己的项目目录，不会把当前电脑未显式连接的本地项目作为远程连接展示。

工作归属和操作确认​

同一具体事项的后续消息会尽量归入已有工作。不确定的归属会等待你检查。在工作预览中展开关联消息，可以拆成独立工作，或移到同一角色的其他工作；调整归属不会重新执行已处理的消息。

需要确认的操作统一出现在 待你处理，从这里进入原会话的审批卡确认或拒绝，无需手动发送“是”。发送钉钉回复时，确认卡展示与该工具调用绑定的待发送正文。选择操作前询问时，写入文件、执行需要提升权限的命令和具有写入性质的 MCP 工具调用使用运行时确认机制。确认只针对当前操作，不提供长期放行规则。该策略目前要求使用 Codex 运行时。

统一处理人工判断​

分身和普通任务提出的结构化问题共用同一条待处理事项。应用在前台时，通过右上角轻提醒发现问题；简单问题可以展开后直接回复。右上角通知铃铛中的 待你处理 打开同名页签，查看对应的原任务或 Issue，并在原界面处理。工作列表和通知条目不再各自提供独立回复表单。

待你处理顶部完整展示所选通知的原问题，并保留实体名称；窄屏隐藏列表后仍可直接阅读问题。待你处理是原实体的容器：任务定位到所选问题的原会话轮次，并展示对应的原生输入卡；Issue 展示已有 Issue 界面，并通过原执行和消息 ID 定位提出问题的 AI 消息及上下文，而非线程起始留言。打开通知时保留阅读位置，主动点击回复后才聚焦输入框。上下文、问题、表单、审批和授权均由原界面展示和处理，不额外抽取或总结对话，不另建回复表单。

容器顶部的 在原界面中打开 返回对应任务或 Issue，并保留源评论定位。需要完整工作区的文件、Review、计划和执行详情操作跳转到原任务；子 Issue 打开对应的原详情，不在待你处理内叠加工作区侧栏。

原任务即使未出现在侧栏列表中，打开后也会恢复它的标题、模型和工作区，支持继续对话。打开原任务不会改变侧栏原有的显示范围。

应用在后台时，按通知设置使用系统通知；支持文字回复的简单异步问题可通过系统通知回复。通知渠道在右上角铃铛的设置中统一管理，账号区域不再保留重复的全局 IM 通知菜单。系统通知还受操作系统权限和通知设置影响。

阅读通知、关闭提醒或标为已读不会完成待办。只有回复被接收或原问题已处理，事项才移入历史；发送失败会保留草稿。设备离线时保留上次已知的问题和草稿，重新连接并核对问题后才能回复。执行审批、连接器登录和复杂表单仍在原上下文处理，普通业务回答不能授予操作权限。Issue 问题的回复写入原评论线程后继续对应执行。

关闭 接收新工作并保存后，分身暂停接收新事项，已有工作仍可继续。来源读取或启动失败会显示错误，可在修正登录、模型或来源设置后重试。执行器保存消息游标、去重记录和归属信息；重启后不会把已经接收的消息当作新消息重复处理。

Issue 的人工介入闭环​

Issue 卡片在标题上方已有的编号／状态行右侧，用图标区分智能体处理、分身处理和等人；等人使用人物叠加小钟图标，旁边只显示主体名字，悬停提示“等待某人处理”，不增加独立一行。执行状态确认正在运行时显示对应智能体或分身；有待回复的问题时优先显示接收人。没有运行中的 AI 时由指定的人处理，未指定则由 Issue 创建人接手，不显示“待分派”等第三种处理状态。排队、失败和离线等详情仍在执行详情中展示，业务状态保持独立。

AI 在绑定的 Issue 执行中提出结构化异步问题后，问题会保存到 Issue，包含原线程、执行身份和处理记录。责任人或协作小组负责人负责把问题分给具体的人；尚未指定接收人时仍由责任人承接，没有指定责任人则由创建人承接，不广播，也不自动选择协调人。AI 使用 list_human_requests 查询问题，原提问执行可通过 set_human_request_blocking 明确标记是否有步骤依赖答案；此操作不转派、不重置等待时间，也不会授予分派权限。责任人使用 assign_human_request 指定处理人。

接收人通过统一的“待你处理”和原 Issue 的问题卡作答。定向通知沿用协作通知设置及已配置的通知渠道。回答写入原评论线程，并交回原执行，不授予对方私人会话或设备的访问权限。读通知不等于处理完成；回答仅排队时仍显示等待接收，原执行接收后才解除对应标记。多个问题分别结算，仍有未解决的问题时继续显示“等人处理”。AI 只等待依赖答案的步骤，其他工作继续。

云端上报问题和源执行修改阻塞标记，需要原活动具备可验证的执行记录，准确关联项目、Issue、Runtime、设备及执行所有者。仅有手工任务绑定，或小组活动尚无匹配的执行证据时，会返回冲突（409），不能仅凭同名设备或推测 owner 继续；应先恢复原执行的可信记录。本地项目仍使用所属执行器的原生来源校验。

看板视图设置提供“仅显示待我处理”，按当前查看者匹配，而不是保存视图的人。离线时保留上次问题和草稿，恢复连接后再校验处理权限。执行审批、登录授权继续使用原生流程，业务回答不能代替授权。

项目看板工具栏还提供一键“待我处理”，它只影响当前查看，不会改写保存视图。全局“待你处理”包含原生项目中轮到自己的事项，以及明确向自己提出的项目问题；同一问题不会同时作为普通事项重复出现。选择项目事项后，在原有双栏内打开真实 Issue 详情，不创建虚构的运行任务。

等待时长与流程分析​

“在你这里”从本轮交接给当前处理人的时点计算，转派给另一个人后重新起算。仅修改问题、阻塞说明、读取通知或保存回答不会重置时钟。普通事项从明确的人类分配、创建人首次接手或本轮 AI 执行结束的可靠时点计算；缺少本轮交接证据的历史记录显示“交接时间未记录”，不用更新时间冒充交接时间。时间按 UTC 保存，界面按自然经过时间展示，不等同于工作日内耗时。

问题保留提出、分派、回复、拒绝送达和执行接收等业务事件，包括事件时间、认证主体、接收人变更和原消息身份，不复制答案正文。以后可按这些证据统计等待分布、跨人交接和成功接续；认证主体不证明实际操作者一定是本人，也不能仅按等待长短、转派次数或回复字数断定个人表现。分析仍须遵循原项目权限，并区分审批职责、外部依赖、AI 执行时间、非工作时间和缺失证据。当前记录是可追溯的业务数据，不是防篡改的人事审计系统；本功能不自动给人贴“瓶颈”或“不干活”等标签。

Issue 分配接收回执​

协作通知会读取本机及支持远程查询的在线执行设备上的分身处理记录。查询失败时，提示会标明失败设备及原因；这表示处理记录未能加载，并不代表 Issue 执行失败。若提示版本不兼容，请更新该执行设备的 Executor，并刷新通知。其他桌面 App 设备不参与远程查询；本机记录仍通过本机执行器读取。

Issue 详情的负责人下拉控件旁用图标显示本次分配的接收情况：白色人形带勾表示本人已读，黑色人形带勾表示分身已接收；悬停可查看状态和时间。同一 Issue、同一负责人的详情刷新期间，顶部保留已显示的回执，避免中断悬停提示；切换 Issue 或负责人时不显示上一范围的回执。本人成功打开详情后记录已读；分身成功接下任务、准备处理后记录接收，无需等待执行完成。两个回执和各自时间独立保留，不会将 Issue 标为完成。通知预览、全部标为已读和后台读取不产生本人已读回执。

分配人和接收人均可查看回执，详情打开期间会自动刷新。底部分配动态中的最近一次有效分配也显示同一份回执，与顶部负责人控件同步更新，不为历史动态增加轮询。转派后回执只显示在最新分配动态上，取消分配后不再显示旧接收人的回执。转派或重新分配后重新记录；历史分配没有可靠回执时，图标提示“暂无接收记录”。云端回执同步失败会在执行器本地保留并补报，失败后逐步延长重试间隔，最长每小时一次；待发送回执最多保留 30 天。重启不会重置等待时间。本地项目回执保存在所属执行器。

Issue 状态或其他属性刷新不会重建同一次指派的回执图标或中断其悬停提示。重新指派（包括再次指派给同一个人）会立即隐藏旧回执，等待本次指派的结果。

分身接收分配时先保存本人设备上的任务绑定和接收回执，再启动执行；交给后台分身安排的事项在进入待处理队列时即记录接收。接收不代表执行成功，之后启动失败也不会撤销已接收的事实。云端上报仍检查当前分配、本人设备和任务绑定；拒绝原因写入诊断日志，不通过放宽权限补写回执。

日历安排与项目负责人​

项目负责人对话和自动处理​

打开 设置 → 通用 → 实验性功能 后，在协作项目中使用 负责人对话。这是现有协作小组负责人的条件入口，不是旧版独立“项目 AI 管理者”页面。

操作步骤与边界
选择小组和设备打开负责人对话，选择当前项目协作小组及设备；没有小组时点设置小组与负责人
与负责人沟通智能体负责人可在私人输入框讨论目标与进展；人工负责人按提示回到原 Issue 协作
工作列表 / 设置用顶部工作列表回到具体事项，或用设置调整小组配置；具体执行仍关联原 Issue
记忆从负责人对话顶部进入记忆；此面板固定当前项目作用域，不会把私人记忆发布到项目
发布到项目顶部发布到项目 → 选择有评论权限的目标 Issue → 填写要公开的指令或结论 → 发布；成功后返回私人对话
让负责人自动处理在支持的智能体负责人及设备下开启；按原项目权限和操作确认处理共享项目事件
接管 / 停止接管前核对原成员与设备并确认；原绑定停止后续派发，已开始工作保留原执行状态；停止不等于删除 Issue
现在查看当前由自己处理时手动触发检查，阅读处理状态或到原 Issue 补充信息；检查成功不代表所有工作完成

发布只共享你填写的内容，不附带私人聊天或记忆；没有可评论的 Issue 时返回项目创建或选择可访问的 Issue。等待权限检查或提交期间按钮可能不可用，不通过换设备绕过权限。

在 我的分身 → 角色档案 → 连接 → 日历 / 定时交办 中记录事项和触发时间，支持一次或周期性触发。到时将事项交给所属分身处理，沿用分身当时的职责、设备、模型和工作目录；整个日历连接统一设置处理方式。日历事项单独保存，返回或关闭时保护未保存的修改；运行记录可进入对应工作查看结果。

通过对话交办未来执行时，分身应先查阅已有工作证据，或立即委派只读检查，核实实际流程、工作目录及必要输入。可以从说明和配置中查到的信息不应反复要求你填写；确实缺少业务选择时，通过问题卡确认，未解决前不创建自动执行安排。要求“走现有自动流程”不代表流程已经核实，也不能把“到时再研究怎么做”当作准备完成。

这里的“只读检查”是预查任务的行为要求，不是新增的沙箱或工具权限模式，也不保证预查任务在技术上无法写入。预查沿用既有权限契约、联网能力和工具审批规则；本轮仅约束调度决策，不扩大或收紧已有权限。

执行方案应写入日程说明，保留原要求，不擅自改成提醒。明确要求提醒时，只需确认提醒内容和时间，不需要检查被提醒事项的执行流程。创建成功仅表示安排已保存，不保证指定时间前完成，也不提前批准发布等外部操作；执行时仍需遵循原生权限、审批和必要条件检查。

任务侧边栏的 已安排是独立功能，保留原有的目标、运行任务、模型和执行环境设置，无需开启实验性功能。它与连接日历分别管理各自的列表、编辑和运行记录。分身工作列表展示具体工作。

项目页面中的负责人就是原协作小组负责人。对话顶部展示小组与负责人姓名，设置仍使用原小组配置。“自动处理项目事件”是在选定设备上启用该负责人的持续处理能力；每个项目与小组只有一个有效成员／设备绑定，切换必须显式接管。私人聊天与记忆仅自己可见，明确发布后才进入所选 Issue。

连接 GitHub 和 GitLab​

角色可接收个人事件或仓库全部可订阅事件。插件提供能力，角色设定决定如何处理。仓库 Webhook 由云端暂存，执行设备离线期间不运行；外部写入保留逐次原生确认。详见 GitHub 与 GitLab 连接。

首次使用分身​

首次打开“我的分身”时，先连接常用应用，再确认开始使用。连接步骤复用分身设置中的项目、钉钉、邮箱等入口，按提示授权并选择关注范围。也可以不连接任何应用，直接点击“继续”。

下一步会列出已选择的内容。点击“开始使用”后保存连接并开启主分身；没有连接时也能正常开始聊天，只是暂时没有应用动态可供分析。以后可以随时在分身设置中添加连接。关闭引导不会保存连接草稿；有修改时会先询问是否放弃。账号授权仍通过原有登录流程完成。

引导不会自动创建定时任务。顶部问号提供每日简报、会议准备、项目跟进、钉钉回复和每周复盘等示例；选择后只填入对话草稿，发送后再确认资料范围和定时安排。

每周复盘可以在对话中交办，或通过 分身设置 → 连接 → 日历 的模板创建。默认时间为每周一北京时间 09:00，回顾本设备上此前七天的工作与对话。可以编辑、暂停或删除，删除后不会自动恢复。
