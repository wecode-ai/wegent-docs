Issue 通知与人工任务 CI 回归

故障依据与修复边界​

PR #3763 的提交 f124f3d2e 在桌面 Core 分片 12、15 失败：

  • project-assignment-notification 的失败快照包含绑定 Task 的入口， 但入口位于视口下方；可见元素点击命令不负责滚动。 场景必须检查展开状态、等待任务行、滚动到入口后再点击，不能删除模型断言。
  • collaboration-issue-comment-notification 首次深链高亮成功， 重载后点击同一条通知不再高亮。同一地址没有产生新的定位请求， 评论组件又按评论 ID 永久去重。

每次打开评论通知生成内部 focusRequest，由现有项目路由传到评论组件。 匹配已有页签时忽略此请求标识，避免重复页签。每个请求只滚动、高亮一次； 后台消息更新不重复高亮。快速再次点击时先结束旧动画，再在下一帧启动新动画。 不增加用户填写字段，不改变模型、设备路由或人工提交权限。

QA 计划​

环境：隔离的 Electron、真实 Backend/Socket.IO/设备，只有模型服务使用场景内的测试服务。 本地使用聚焦 Vitest 验证，完整桌面验收由现有 GitHub CI Core 分片执行； 不操作个人 WeWork 窗口，不通过重跑、扩大超时或跳过断言掩盖失败。

前置条件操作预期
人工 Issue 已绑定远程 AI 草稿 Task改变新会话默认模型，展开并滚动到已有 Task，再打开使用绑定模型，不继承新会话默认值；原 Issue 仍由人工提交
评论通知首次打开深链定位目标评论在原有时间预算内滚动并高亮，其他评论不高亮
重载后仍打开同一评论，旧动画已结束从通知中心再次点击原通知复用页签，产生新请求，重新高亮并保存已读状态
高亮尚未结束快速再次定位同一评论重启动画，不延续旧动画的剩余时间
定位请求没有变化后台消息刷新或普通重渲染不重复滚动和高亮
评论尚未加载，或已离开评论加载目标评论；离开后再返回加载后定位；返回可以再次定位
定位动画已排队卸载组件清理动画帧和定时器

现有 CI 场景保留真实远程设备、任务绑定、交付、人工提交/验收、已读持久化断言。 失败时保留界面快照和运行日志，成功时检查截图。 场景使用各自独立的用户、项目和运行目录，交由桌面 runner 的清理流程回收。

验证记录​

2026-10-09：修复前新增的重复通知路由及评论高亮断言均失败，修复后均通过。 聚焦测试 7 个文件、177 条用例通过，覆盖通知路由、评论定位、Issue 编辑器和人工任务抽屉。 ESLint、Prettier、TypeScript 和两个场景的语法检查通过。 本地结果不代表真实远程设备或桌面 E2E 已通过；最终结论以修复提交的 CI 为准。

推送后 main 新增 Issue 归档功能，导致“更多信息”菜单冲突。 合并保留归档文案、回调和点击外部关闭弹层的行为；补充单测验证两者同时可用。 归档相关的共享组件、桌面编辑器和 Backend 接口用例需在合并后重新验证。

main 随后合入统一 Issue 执行状态与回复逻辑。合并必须同时保留智能体 Team/ 模型绑定和执行线程、工作目录、Issue 会话上下文，不能因没有选择模型而丢失上下文。 聚焦测试发现续跑成功后的状态推送漏传 to_view 所需的数据库参数，已修正； 验证原会话续跑、忙碌任务排队、重新指派后回复和人工绑定的智能体模型不变。 抽屉重开单测直接建立活动项目，复用交互设备，明确断言旧面板已关闭， 保留迟到的任务地址不能覆盖新面板的断言，不扩大用例超时。

同一处理人取消后重新指派​

提交 f5bbaab0c 的 Core 分片 12 在人工验收后重新指派阶段失败： human_work.state 仍为 accepted，场景要求新一轮指派为 none。 旧版 PATCH 接口只清空负责人字段，没有撤销活动流里的指派事件， 同一处理人的后续指派因此被错误去重。取消直接人工指派时复用现有 指派事件撤销服务，与负责人字段修改保持在同一版本校验事务内。

回归覆盖待验收、已完成 Issue 重新指派给原处理人或其他处理人； 新指派使用新事件 ID，保留 Issue 原状态，显式接手后才进入进行中。 未取消时重复指派仍幂等；版本冲突不撤销指派；工作流步骤的指派不被误删。 不删除已有验收记录，不改变桌面 E2E 断言或超时。

2026-10-10 主分支合并回归​

保留 main 的 Issue 标题/描述行内编辑、附件预览及个人任务工作区选择， 同时保留人工处理、AI 草稿、标签编辑和点击外部关闭属性弹层。 普通个人任务不继承智能体的项目执行环境；人工 AI 辅助继续使用最新保存的 项目设备/目录和人工指派绑定。评论通知统一使用内部 focusRequest 参数。 时间转换复用可配置的数据库时区，SQLite 及已有时区的时间不被重复偏移。

创建项目/切换视图与成员、机器人、小组指派的组件测试拆为独立场景， 每个场景建立自身前置条件并保留原断言，不扩大超时或添加重试。 合并后检查共享组件、桌面编辑器/抽屉/通知、Web 详情和数据库时间回归； 聚焦单测和类型检查不代表真实远程设备或桌面 E2E 验收。
